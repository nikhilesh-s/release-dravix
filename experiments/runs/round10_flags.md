# Round 10 (round10_physics) -- worker flags

Items marked FLAG skipped a candidate or need an orchestrator decision; NOTE items record how a definition was implemented, for the critic.

- NOTE (GP input width d). `RBF(length_scale=np.ones(d))` is ARD, so it needs one length scale per GP input column. The GP inputs are SimpleImputer(median, add_indicator=True, keep_empty_features=True) -> StandardScaler, so d = imputer output width = n features + one indicator per feature with a missing value in that training fold (set at fit time per fold). Applies to r10_phrr_g1/g2 and r10_cr_g1/g2.
- NOTE (FIGRA mcc_t_onset_C). "definitions as r10_phrr_f1": taken as the exp074 definition, i.e. the per-material mean of `t_onset_bc_C` (also FGC's T1), not the raw `t_onset_C`. exp119's own 9 features are unchanged (its `mcc_total_hr_kJg` stays the raw `total_hr_kJg` mean); FGC uses the bc columns as defined in the config.
- NOTE (LOI m1 pipeline). make_pipeline cannot size `monotonic_cst` before the imputer has seen the fold (indicator count varies per fold), so RF_m / ET_m are a 10-line wrapper (`MonoImp`) that fits the same imputer, builds c (+1 at total_fr_wtpct, el_P; 0 elsewhere incl. indicators) to the output width, then fits the unchanged RF/ET with `monotonic_cst=c`. Self-test: with no constrained column it equals make_pipeline(imputer, est) bit for bit; with the constraint, predictions are monotone. m0 uses make_pipeline directly.
- NOTE (LOI s1). StringEncoder is fit_transform-ed on the training rows of each fold and applied (transform) to that fold's test rows, for protocol B and protocol C. Its 8 columns are appended after the 51 exp115 columns and all three members (RF, ET, Ridge with its own imputer/scaler) see the 59 columns. skrub 0.10.1 `StringEncoder` exists and needs no download.
- NOTE (environment). OMP_NUM_THREADS / VECLIB_MAXIMUM_THREADS / OPENBLAS_NUM_THREADS / LOKY_MAX_CPU_COUNT = 3 (worker limit); the record runs used 1. Forest outputs do not depend on n_jobs; each step-1 reproduction is checked within 0.001 (the round config's tolerance, stricter than the gate config's 0.002) on mean, ci_lo and ci_hi.
- NOTE (warnings). Apple Accelerate raises spurious "encountered in matmul" RuntimeWarnings; they are filtered, and every OOF array is checked with isfinite. GP ConvergenceWarnings are counted per candidate (`gp_warnings` in the result JSON), not suppressed silently.
- NOTE (LOI protocols). Protocol A (50 random splits) is not computed for round-10 LOI candidates (not in the config's reported_only list); protocol C and the paper-level pooled CI are computed as exp115 reports them.
